The reframe


Four places DebugAssist waits for a person.
One expert answers each.


DebugAssist takes a GitHub bug and returns the fix, why it shipped, and a guard. At four points the run needs a judgment call, so it stops and waits. With this server connected, it calls an expert over MCP instead — and gets back a typed answer it can act on.




1 · Triage
Is this a real defect?
NOT A DEFECTNEEDS PERSON
→ defect_triage
  • DEFECT
  • NOT_A_DEFECT
  • NEEDS_PERSON
  • DECLINED
One of four states. Confidence is checked before the defect call, so a weak signal is handed to a person instead of guessed.


2 · Locate
Which file and lines hold the cause?
CAUSE NOT FOUND
→ cause_locator
  • CANDIDATES
  • CAUSE_NOT_FOUND
Up to three ranked file-and-line ranges, each taken from the repo listing, each with what would confirm it or rule it out.


3 · Validate
Does the test actually prove the fix?
FIX NOT VALIDATEDTEST FLAWED
→ qe_ic_debugassist
  • SOUND
  • UNSOUND
  • UNEVALUABLE
A verdict on the test that names the check it rests on and what would flip it. A “sound” with no named check, or in vibes language, comes back unevaluable.


4 · Guard
What conditions let this ship?
GUARD NOT WRITTEN
→ allspaw_debugassist
  • CONDITIONS
  • DECLINED
System conditions, never a culprit — each with its own test for when it holds and when it fails, so the guard can be written against it.






Every answer ships a falsifiable test that resolves when the real outcome lands. A pass rate is published once an expert has 30 resolved tests, and not before.

The cost


Each one costs a human context-switch.


You know the shape: a run reaches a load-bearing moment and waits. You context-switch in, read the state, make the call, context-switch out. Multiply by every run, every agent, every on-call engineer.


The experts don't replace judgment — they answer the routine cases at machine speed, so humans only get called for the genuinely hard ones. Fewer pauses, fewer switches, faster runs.

Release notes v0.1.0 · 2026-10-07


Six domain expert seats with measured pass rates, stateless HTTP transport, and a falsifiable calibration loop — built to be queried by a debugging pipeline where runs stall for human judgment. Seats, readiness, and calibration are covered in the sections above; what's still in motion:


Install


    

  1. Get MCP_API_KEY from the operator and export it: export MCP_API_KEY=…
    2. 

  2. Add the server. Claude Code: claude mcp add --transport http domain-expertise https://domain-expertise-mcp.onrender.com/mcp --header "Authorization: Bearer $MCP_API_KEY" — or paste the JSON config above into your client's MCP config (Claude Code expands ${MCP_API_KEY}; other clients may need the key written in).
    3. 

  3. Check you hold the server's key: printf %s "$MCP_API_KEY" | shasum -a 256 | cut -c1-8 must print … (the server's fingerprint, read live from /health; the key itself is never shown).
    4. 

  4. Smoke test: curl -s -X POST https://domain-expertise-mcp.onrender.com/mcp -H "Authorization: Bearer $MCP_API_KEY" -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' lists the tools. A 401 means the key is wrong.
    5.
